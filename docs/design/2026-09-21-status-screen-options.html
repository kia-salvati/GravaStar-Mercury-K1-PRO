Mercury K1 PRO — status screen, four structures

Stage 1 is read-only. Every frame below is the real 480 × 640 window; the width toggle stretches it to 900 to check it does not go hollow. Inside a frame, click any value to change the preview state (connection, battery, effect, stages, colour mode, sleep) — those clicks are design-only and stand in for readings the keyboard will send.

A — Readout stack

One vertical column, top to bottom in order of how often you glance: identity and link, then power as the only large element, then lighting as label/value rows, then a bottom tab bar to the other three areas. It behaves like a tray utility, not a page.

Structure

  • Header carries the device name, firmware and a three-slot link indicator (Wired / 2.4G / BT). BT is drawn as an empty slot now so Bluetooth is one more value, not a redesign.
  • Power block is the single large number on screen. On cable it becomes a full-weight sentence, not a greyed-out zero.
  • Lighting and Power groups are strict 92 px label / value rows; long effect names wrap inside the value column instead of pushing the label.
  • Sleep timer on cable stays in place but drops to muted text and says why — the row's absence would read as a bug, not a state.

Navigation

  • Bottom tab bar: Device (home) · Lighting · Keys · Macros. At 900 px the bar becomes a horizontal row of labelled buttons; the body splits into power (left) and lighting (right).

Try

  • Click the link indicator → wired; battery becomes "not reported on cable", sleep row mutes.
  • Click the battery number → cycles 100 % full → 23 % charging (pulse) → 61 % → 8 % low.
  • Click the effect name → picker; brightness / speed blocks → next stage; colour → Colour Mixing.

Default state here

  • Happy path as read from the real board: 2.4G, 100 % full, Windmill, brightness 1, speed 0, #ffffff, sleep 1 min.

B — Tiles + doors

A dashboard of unequal tiles, where the tiles that are the home screen (power, effect, sleep, firmware) look different from the tiles that lead somewhere (dashed "doors" to Lighting, Keys, Macros). Navigation is content, not chrome.

Structure

  • Identity strip with the connection as a pill (click to toggle).
  • Power tile spans the row; it is the only tile with a 40 px number. On cable it changes shape to a two-line statement with the same weight.
  • Effect tile shows the name large and the three secondary readings (brightness stages, speed stages, colour) as a wrapping meta row — long names like "Dream Rainbow" still fit at 480.
  • Sleep tile dims on cable and prints "wireless only" instead of a value.
  • Doors carry a one-line teaser each ("3 layers · 84 keys", "512 B budget"). Macro usage is not shown as a number because Stage 1 has not read it — the budget is the only certain fact.

Navigation

  • The three doors. At 900 px the grid goes to four columns and the doors stack on the right as a list.
  • Cost of this structure: B fills 900 × 640 least well. Tiles are top-anchored and the lower third stays empty; stretching them to fill produced hollow boxes, so they are left at natural height. If the wide window matters, B is the weakest of the four.

Try

  • Click the connection pill (starts wired to show the unknown-battery state), the stage blocks, the effect name, the swatch.

Default state here

  • Mixed: wired, battery unknown, Windmill, brightness 1, speed 0, single colour #ffffff — the state the board is in when plugged in.

C — Keyboard first

The 84-key silhouette is the readout: keys are cut out of the plate and the layer behind them is the current effect — colour, brightness stage (as opacity, four levels), speed stage (as animation period) and Colour Mixing all render on the board. A chip strip under it carries the exact values; a segmented control switches what the board represents in later areas.

Structure

  • Board on top (keeps its 16 × 6 unit proportions at both widths), effect name and firmware in a caption line. At 900 px the board is capped at 250 px tall and centred; caption + chips go left, area control + detail list go right.
  • Status strip: one chip per fact. Facts that need the reader's attention (battery unknown on cable, charging) get an accent border rather than muted text.
  • Segmented control: Device · Lighting · Keys · Macros. In Keys the same board becomes the remap surface; in Lighting, the colour surface.
  • Detail list below with the sentence forms ("Not reported on a cable connection", "Wireless only — not in effect on cable").

Motion, and why

  • Only animated effects animate (Windmill spins, Wave / Sine Wave / Waterfall / Dream Rainbow slide, Stars twinkle, Blooming pulses). Static effects are static. Off is dark. Honours prefers-reduced-motion.
  • Speed stage 0 → 12 s period, stage 4 → 2 s. Brightness stage 1–4 → 35 / 55 / 80 / 100 % glow.

Try

  • Click the effect chip and pick Windmill, Wave, Stars, Off. Click brightness/speed chips to watch the board respond. Click the colour chip for Colour Mixing. Click the battery chip (starts 23 % charging).

Default state here

  • Mixed: 2.4G at 23 % charging, effect Dream Rainbow (a long name that also overrides single colour), brightness 3, speed 2, sleep 1 min.

D — Status rail + panel

The left rail is not a menu with a status stuck on it — it is a persistent glance strip (link, battery, effect swatch) that stays visible in every area, with the four area buttons under it. The panel is the full Device sheet. The point: when you are three layers deep in Key Remapping, the battery is still in the corner.

Structure

  • Rail at 60 px: three glance glyphs with tiny values, then four icon buttons. At 900 px the rail widens to 200 px and the glyphs grow their labels — no second layout, the same elements gain text.
  • Panel: identity, a Connection statement (big sentence + note block), then Lighting as two-column spec rows, then Sleep. Notes use an accent left border when the reader must know something (battery not reported), a neutral one for plain context.
  • On cable the Sleep section is removed and its absence is explained in the Connection note — hiding with a reason.

Navigation

  • Rail buttons. This is the conventional desktop shape; it is kept distinct from the vendor's by having no hero image and no empty top: the panel is dense from the first line.

Try

  • Click the rail glyphs (link, battery, swatch) as well as the panel values. Widen to 900 px to see the rail labels appear.

Default state here

  • Mixed: 2.4G at 61 %, effect Blooming in Colour Mixing mode (no single hex to show), brightness 4, speed 4, sleep 20 min.

Tokens, measured

Contrast ratios computed at load from the live CSS custom properties for the current theme. Body text and muted text must clear 4.5 : 1 on every surface they are placed on. --text-3 is the most muted colour used for running text and is only ever placed on --bg, --surface and --s2.
